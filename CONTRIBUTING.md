# Contributing

Thank you for considering a contribution. This is a docs-only kit and is still a draft.

## What helps

- Corrections to unclear or unsafe guidance.
- New scenario cards for real failure patterns, described generically.
- Checklist items that are concrete and checkable.

## Ground rules

- Keep it vendor-neutral. Do not promote or disparage specific products.
- Write original text. Do not paste text from other sources; link and summarize in your own words.
- Never include secrets, personal data, exploit code, or details about a specific organization's systems. See [SECURITY.md](SECURITY.md).
- Never suggest testing destructive or externally visible actions in production.
- No claims of certification, compliance, or guaranteed safety.

## Process

Open an issue describing the change before large edits. Contributions may not be accepted.

Social Media handles issue intake and triage, coordinating with the CTO on technical and security matters. Response times are not guaranteed. Use public issues only for non-sensitive documentation feedback; do not include secrets, private data, vulnerabilities or exploit details. See [SECURITY.md](SECURITY.md) for the intended private route, which is not yet enabled or verified.
